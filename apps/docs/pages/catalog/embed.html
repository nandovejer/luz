Example

NASA’s video of John Young’s salute on the Moon, with a poster of this site. Nothing is requested from the video service until you press the button and agree: the example asks first, as a site that wants consent would, and only then loads the player. Its answer is stored under its own key, luz-consent-demo, so it does not count as an answer for this site.

Play video: John Young’s Lunar Salute on Apollo 16

This video plays from an outside service, which learns your IP address and may set cookies.

Without JavaScript the poster is a link to the video.

This is the one page of this site that may load another site, and only after you press the button and agree: the security policy of the site lets this page, and no other, frame www.youtube-nocookie.com.

Known issues

Two things to know before you rely on it.

  • “Always play” writes the answer of the cookie banner, under its key luz-consent (or the key of data-luz-consent-key), with a fixed expiry of 180 days: it does not read the banner’s data-luz-consent-days, so a banner set to another period replaces the answer with its own the next time the visitor answers it.
  • It has not been tested with a screen reader.
Code Design

Code

Copy the markup

The link is the page without JavaScript, so write it as the page you want a reader to land on: it points to the video where it lives. src is the address of the player, in full, as the other site gives it (here, the privacy-enhanced embed address that YouTube gives for a video); LUZ builds no address and names no provider. The poster is your own image, on your own server: a poster fetched from the other site would reach it on page load.

catalog.min.js loads the element’s own file, embed.min.js, when it scans the page; a page without catalog.min.js loads that file on its own.

HTML 
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.3.0/dist/catalog.min.js"></script>

<luz-embed src="https://www.youtube-nocookie.com/embed/g5aPoRtF2vw?autoplay=1" consent="external">
  <a class="luz-embed__link" href="https://www.youtube.com/watch?v=g5aPoRtF2vw">
    <img class="luz-embed__poster" src="/media/apollo-16-poster.jpg" alt="" width="1280" height="720" loading="lazy">
    <span class="u-sr-only">Play video: </span>
    <span class="luz-embed__title">John Young’s Lunar Salute on Apollo 16</span>
  </a>
  <div class="luz-embed__ask" data-luz-embed-ask hidden>
    <p>This video plays from an outside service, which learns your IP address and may set cookies.</p>
    <div class="o-actions">
      <button class="luz-btn luz-btn--primary" type="button" value="once">Play this video</button>
      <button class="luz-btn luz-btn--secondary" type="button" value="always">Always play outside videos</button>
      <button class="luz-btn luz-btn--ghost" type="button" value="cancel">Not now</button>
    </div>
  </div>
</luz-embed>

Your scripts can ask what the element would load:

JS 
import { playerURL } from "@luz-ds/catalog/embed";

// The address the element would load, or null when it stays a link
const url = playerURL(document.querySelector("luz-embed"));

Variants and options

There are no variants. The ratio is a property, and the hooks are attributes.

Class or attributeEffect
<luz-embed>
The custom element the module defines: a block with the ratio of the frame. It wires itself when it connects
src
Required. The full address of the player, written by you: https:, or of the page’s own origin. Anything else (javascript:, http: of another origin, a typo) leaves the link
consent
The name of a category of the cookie consent (a lowercase letter, then lowercase letters, digits or hyphens, 32 at most). Until it is granted nothing is requested from the player’s origin, and a click asks first. Without an ask block and without the category granted, it stays the link
data-luz-consent-key
The storage key of the choice, which must start with luz-; luz-consent, the banner’s, by default
--luz-embed-ratio
The ratio of the frame, 16 / 9 by default. Set it on the element: style="--luz-embed-ratio: 4 / 3"
.luz-embed__link
The link of the page without JavaScript: it holds the poster and the title, and takes the frame whole. With JavaScript it becomes a button.luz-embed__play with the same children, so its name does not change
.luz-embed__poster, .luz-embed__title
Your image, which covers the frame, and the title, on a scrim at its foot
.luz-embed__ask with data-luz-embed-ask
Optional, hidden in the markup: the question that shows when the click needs a consent that is not there. Its buttons have a value: once, always or cancel
data-luz-state
Written by the script: ready, ask or playing. Style it, never set it
playerURL(el)
Exported by @luz-ds/catalog/embed: the validated address of the element, or null

How it works

CSS from @luz-ds/catalog and a file of its own, @luz-ds/catalog/embed (dist/embed.min.js, under 1.5 kB compressed), which defines <luz-embed>. It uses no library, and the player’s own script, if any, runs only inside the frame, once loaded. A native video or audio does not need it: use the player. This is for what only another site can show.

  • Before the click: the page holds a poster and a button, and requests nothing from the other site. When the pointer goes over the button, or focus reaches it, the browser is told to open a connection to the player’s origin (a preconnect, once per origin), unless the site wants consent and it is not granted.
  • The click: if nothing needs consent, or it is granted, the frame is written with autoplay permission, and focus goes into it. If consent is needed, the question shows in its place and focus goes to its first button.
  • The question: value="once" plays this video. value="always" plays it and stores the category, as the cookie banner does, in localStorage as {"version":1,"expires":…,"asked":[…],"granted":[…]}, dispatches luz:consent on document and unlocks every other embed with that category. value="cancel" goes back to the poster, with focus on its button. Escape does nothing; Not now is the way back.
  • The frame: it has the title of the video, allow for the features players use, allowfullscreen and referrerpolicy="strict-origin-when-cross-origin", which some players need to accept the embed.
  • The script writes no text: every word is in your markup, in the page’s language.

A server that builds your pages can write src and save the poster when the content is saved, so a reader never contacts the other site before choosing to.

Without JavaScript

The poster is a link with a visible title that opens the video where it lives, and the question stays hidden. It does the same when src is not valid, and when the category is not granted and there is no question to ask.

Keyboard and ARIA

  • Keys: Tab reaches the button; Enter or Space presses it, as on any button. In the question, Tab goes through its buttons. Escape does nothing.
  • Name: the button has the name of the link it replaces: the hidden words “Play video:” then the title.
  • Focus: to the first button of the question when it shows, into the frame when the player loads, back to the button on Not now. Once the player is in the frame, its own keys and controls are the other site’s, and the page cannot reach them.
  • Language: the question and the names are yours, in the page’s language. The player’s are the other site’s.

Design

When to use

Use it for a video, a map or any player that a page takes from another site. Loading such a frame sends the reader’s address to that site, and its script weighs more than the rest of the page; a poster and a button cost one image.

When not to use

Do not use it for a video or sound you host: that is the player, which has controls that LUZ styles and a keyboard that LUZ tests.

  • Do not use it for a link to a page that happens to have a video: that is a card or a link.
  • Do not use it to hide a frame the reader never asked for: it loads only after a click.

It replaces the iframe code that the other site gives you, and the facade scripts for one provider. Nothing in LUZ is removed.

Do and don't

Writing the content

The title is the title of the video, as the reader would say it, and the hidden words before it say what the button does: “Play video:”. Do not repeat the title in the poster’s alt, which stays empty because the title already names it.

  • Say in the question who the service is by what it is (“an outside service”) and what it learns (“your IP address”, “may set cookies”), in a sentence.
  • Write the buttons as the action and the thing: “Play this video”, “Always play outside videos”, “Not now”. Never “OK” or “Yes”.
  • Choose a poster whose important part is in the middle: the play mark covers it.

Which level do I need?

  • Your own components, LUZ's colours and spacing: level 1, tokens only.
  • Ready-made buttons, forms, tables and dialogs: level 2, tokens and core.
  • Whole pages: shell, page header, footer, search: level 3, the Catalog, all three packages.
  • A landing page, with its header, hero and blocks: level 3 and the patterns for that kind of site, which are catalog components.

Level 1: tokens only

CSS custom properties: the colour, space and type scales, the font roles, the breakpoints and the motion durations, and the colours of light, dark and high contrast. No other LUZ package is needed.

$ pnpm add @luz-ds/tokens
HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">

With a bundler such as Vite, import the files instead of adding tags. A href cannot name a package: these paths are for import only.

Bundler 
import "@luz-ds/tokens/css";
  • Running text and headings use ET Book, an MIT-licensed font that ships with the tokens. Controls, labels and tables use the system sans, and code the system mono.
  • Bringing your own fonts? Load dist/tokens.min.css instead: the same tokens without any @font-face.
  • Check your own colours against the WCAG ratios with npx @luz-ds/tokens@0.2.1 check-contrast, or in the browser.

Level 2: tokens and core

The 29 components, the styles of bare HTML elements, and optional JavaScript. Load tokens first.

$ pnpm add @luz-ds/tokens @luz-ds/core
HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css">

<!-- Optional: copy buttons, tabs, players, the color mode -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.js"></script>
Bundler 
import "@luz-ds/tokens/css";
import "@luz-ds/core/css";

// Optional: copy buttons, tabs, players, the color mode
import "@luz-ds/core";
  • Every page works without the script. See what each JavaScript module adds.
  • Need a single component? Load dist/base.min.css plus the file you want, for example dist/components/button.min.css.
  • Markup you cannot add classes to, such as Markdown or a CMS? A bare button, field or table already has its look in luz.css. On a page that already has a design, load luz.conditional.css instead and mark the zone with data-luz.

Level 3, the Catalog: tokens, core and catalog

The site's navigation and the pieces with a script or an identity of their own: navbar, sidebar, terminal, timeline, search, cookie consent, color mode, language switch, submenu, announcement and FAQ, and the patterns of a kind of site. The catalog needs core and tokens.

The page structure of each kind of site, from the header to the footer, is in the catalog too, one stylesheet per pattern: see Kinds of site.

The catalog has a stylesheet per component: link the ones the page uses, after core.

$ pnpm add @luz-ds/tokens @luz-ds/core @luz-ds/catalog
HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/components/search.min.css">

<!-- Optional: core behaviours, and the site search and cookie banner -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.js"></script>
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/catalog.min.js"></script>
Bundler 
import "@luz-ds/tokens/css";
import "@luz-ds/core/css";
import "@luz-ds/catalog/components/search.css";

// Optional: core behaviours, and the site search
import "@luz-ds/core";
import "@luz-ds/catalog";

Kinds of site

To start a landing page, a blog, an app or a documentation site, go to Kinds of site: a prompt for any LLM, and the recipes of each part to copy.

There is no package for a kind of site. Its patterns are components of the catalog, one stylesheet each, named for what the piece is, <block>.css. Install level 3, then link the files your page uses, after core:

  • Landing page: site-header, hero, main, section, stat, site-footer and glow: the header, hero, sections and footer.
  • Blog or newspaper, with any CMS: site-header (or masthead for a newspaper), page-header, article-header, article and site-footer: the header, page header, article header, table of contents and footer.
  • Web application: app-bar and dashboard.
  • Documentation site: docs-layout, doc-header, page-rail, example, do-dont, pager and page-footer.

The catalog has a page for each pattern, and says which kinds of site it fits best.

HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/components/site-header.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/components/hero.min.css">
Bundler 
import "@luz-ds/tokens/css";
import "@luz-ds/core/css";
import "@luz-ds/catalog/components/site-header.css";
import "@luz-ds/catalog/components/hero.css";
  • Link the files of a kind in the order of the list above.
  • Link hero with section: the head of a section shares its rules with the hero.
  • None has a script. The catalog's script is optional: with the table of contents of a blog, it marks the section in view; with the sidebar of an app, it marks the current link and closes the drawer when a link is followed. Core's script does not do this.

Before you ship

  • npm and pnpm install the lower levels for you. Yarn only warns, so list every package, as above.
  • On a CDN, pin an exact version and add an integrity hash with crossorigin="anonymous". Compute the hash from the file you load, as below.
  • The core and catalog scripts warn in the console when the level below is missing.
  • Set lang on <html>: core's scripts write their text in that language (English and Spanish ship).
Shell 
curl -s https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css | openssl dgst -sha384 -binary | openssl base64 -A

Write the result as integrity="sha384-…" on the tag that loads that file, and repeat it for each file.

A hash on a script covers that file only, not the files it loads later. catalog.min.js loads search.min.js on a page with a search and cookie-consent.min.js on a page with a cookie banner and color-mode.min.js on a page with an Auto color mode.

Give each one its own hash in an import map, before the first module script. It works in Chrome 127, Safari 18 and Firefox 138 and later; an older browser ignores it and loads the files unchecked.

A <link rel="modulepreload"> with a hash is not a guard in Safari or Firefox: use it as a performance hint only.

HTML 
<script type="importmap">
{
  "integrity": {
    "https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/search.min.js": "sha384-…",
    "https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/cookie-consent.min.js": "sha384-…",
    "https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/color-mode.min.js": "sha384-…"
  }
}
</script>
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/catalog.min.js" integrity="sha384-…" crossorigin="anonymous"></script>

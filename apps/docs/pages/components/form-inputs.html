Variants and options

How it works

Without JavaScript

Keyboard and ARIA

  • Tab moves focus to the swatch. Enter or Space opens the picker, whose keys are the system's.
  • The label is the name. A swatch is a color alone: write the value as text where the reader needs it.

Contrast and focus are in the Design tab.

Design

When to use

Use a color field when the reader may choose any color: a label, a tag or a chart.

  • Start with value, so the swatch is not black.
  • Check the contrast of the color on your side: the picker allows any.

When not to use

A color field is for a free choice, not for a short list.

  • A few named colors: radio buttons with the names.
  • A color your design fixes: do not ask the reader.

Do and don't

Writing the content

  • Label it for what it colors: "Accent color", "Label color".
  • Name the color where it matters: a swatch alone says nothing to some readers.
  • The error says what to change: "Choose a darker color."

File

A button that opens the system's file chooser, and the name of the chosen file.

PDF or PNG, up to 5 MB.
Code Design

Code

Copy the markup

The class .luz-input styles the button and the name. The form needs enctype="multipart/form-data" to send the file:

HTML 
<form method="post" enctype="multipart/form-data">
  <div class="luz-field">
    <label class="luz-field__label" for="file">Attachment</label>
    <input class="luz-input" id="file" type="file" accept=".pdf,.png" aria-describedby="file-hint">
    <div class="luz-field__helper" id="file-hint">PDF or PNG, up to 5 MB.</div>
  </div>
  <button type="submit">Upload</button>
</form>

Variants and options

  • accept: the types the chooser offers, such as .pdf or image/*.
  • multiple: several files; required: the browser stops the form until one is chosen.
  • The error and disabled states are the Text field's.

How it works

A native <input type="file">. .luz-input[type="file"] styles the button with tokens (::file-selector-button). Its words, "Choose file" and "No file chosen", are the browser's, in the reader's language. accept only filters the chooser: check the type and the size on the server.

Without JavaScript

The field works and sends its file with the form, with method="post" and enctype="multipart/form-data".

Keyboard and ARIA

  • Tab moves focus to the button. Enter or Space opens the chooser.
  • The label is the name; the hint says the types and the size.

Contrast and focus are in the Design tab.

Design

When to use

Use a file field when the reader sends a file from their own device.

  • A résumé, a photo or an attachment.
  • Say the accepted types and the size in the hint, before the reader chooses.

When not to use

A file field cannot check what it receives.

  • Do not rely on accept for safety: it filters the chooser, and a reader can pick anything. Check on the server.
  • The address of a file that is already online: a URL field.

Do and don't

Writing the content

  • Label it with a noun: "Attachment", "Photo".
  • The hint gives the types and the size: "PDF or PNG, up to 5 MB."
  • The error says what to change: "The file is larger than 5 MB. Choose a smaller one."

Range

A slider for a value on a scale, the place of the thumb matters more than the exact number.

Code Design

Code

Copy the markup

A slider with min, max and step, and an <output> that shows its value. The slider shows no number of its own, so the output is updated by a few lines of your own script:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="volume">Volume <output class="luz-output" id="volume-out" for="volume">50</output></label>
  <input class="luz-input" id="volume" type="range" min="0" max="100" value="50">
</div>
JS 
const range = document.getElementById("volume");
const output = document.getElementById("volume-out");
range.addEventListener("input", () => {
  output.value = range.value;
});

Variants and options

  • min, max, step: the scale and the size of a step.
  • disabled: faded, skipped by Tab, not sent. A range has no read-only state.
  • With no <output> the reader cannot see the number: always add one.

How it works

A native <input type="range">. .luz-input[type="range"] sets accent-color to --luz-brand-primary, so the thumb and the filled track follow the brand. LUZ has no script for the output: yours listens to the input event.

Without JavaScript

The slider works and submits its value. Without your script the output keeps showing the starting value.

Keyboard and ARIA

  • Tab moves focus to the slider. Left and Down take away one step, Right and Up add one. Home and End go to the ends.
  • The label is the name; tie the output to the slider with for.

Contrast and focus are in the Design tab.

Design

When to use

Use a range when the reader sets a value by feel and a near answer is enough.

  • Volume, brightness or a rough budget.
  • Show the value next to the slider, and set min, max and step to what you need.

When not to use

Do not use a range when the exact number matters or the scale is long.

  • An exact amount: a number field.
  • A few named levels: radio buttons with the names.

Do and don't

Writing the content

  • Label it for what it sets: "Volume", "Brightness".
  • The output holds the number only; put the unit in the label: "Volume, %".
  • Say the ends of the scale in the hint if they are not obvious.

Textarea

A field for text of more than one line, such as a message or a description.

Up to 500 characters.
Code Design

Code

Copy the markup

A native <textarea>. .luz-input--textarea gives it its height, and maxlength its limit:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="textarea">Message</label>
  <textarea class="luz-input luz-input--textarea" id="textarea" rows="4" maxlength="500" aria-describedby="textarea-hint"></textarea>
  <div class="luz-field__helper" id="textarea-hint">Up to 500 characters.</div>
</div>

Variants and options

  • rows: the starting height; the reader drags it taller, never wider.
  • maxlength, minlength: the browser checks them; say the limit in the hint.
  • The states are the Text field's: error, required, disabled and read-only.

How it works

A native <textarea> styled like a text field, at least 80 px high. A textarea with no class looks the same. LUZ has no character counter.

Without JavaScript

The field works and submits with its form.

Keyboard and ARIA

  • Tab moves focus in and out. Enter adds a new line: it does not send the form.
  • The label is the name; the hint says the limit.

Contrast and focus are in the Design tab.

Design

When to use

Use a textarea for free text of more than one line.

  • A message, a comment, a description or a bio.
  • Say the limit in the hint, if there is one.

When not to use

Do not use a textarea for a short answer, nor for formatted writing.

  • A name, a title or a reference: a text field.
  • Text with headings and links: your own editor. Never build a textarea from a <div contenteditable>.

Do and don't

Writing the content

  • Label it for what to write: "Message", "Description".
  • The hint gives the limit: "Up to 500 characters."
  • The error says what to change: "Write at least 20 characters."

Example

A group of questions with their answers: opening one closes the one that was open.

What is a design token?

A named value, such as a color or a space, that components read instead of a literal.

Why only one open at a time?

The same name on each details connects them: opening one closes the other.

Does it need JavaScript?

No. The browser opens, closes and groups them.

Known issues

Two points to know before you rely on a named group.

Exclusive group. The name attribute works in Chrome and Edge 120, Safari 17.2 and Firefox 130, all from September 2024 or earlier, so it is not yet Baseline widely available. In an older browser each panel opens on its own: nothing is lost.

Screen readers. How NVDA, JAWS, VoiceOver, TalkBack and Orca announce an exclusive group has not been tested for LUZ, and no support data was checked. The grouping of an exclusive set is not described to assistive technology: the HTML accessibility mapping for it is still an open issue (see the Open UI explainer).

Code Design

Code

Copy the markup

A bare details needs no class: a summary and a divider, with no box.

HTML 
<details>
  <summary>What is a design token?</summary>
  <p>A named value that components read.</p>
</details>

.luz-accordion adds the box and the group. With the class (each … is the Chevron end or Chevron down SVG of the Icons page):

HTML 
<div class="luz-accordion">
  <details name="faq" open>
    <summary><span>What is a design token?</span><svg class="luz-accordion__end" data-luz-flip aria-hidden="true">…</svg><svg class="luz-accordion__down" aria-hidden="true">…</svg></summary>
    <p>A named value that components read.</p>
  </details>
  <details name="faq">
    <summary><span>Does it need JavaScript?</span><svg class="luz-accordion__end" data-luz-flip aria-hidden="true">…</svg><svg class="luz-accordion__down" aria-hidden="true">…</svg></summary>
    <p>No.</p>
  </details>
</div>

Variants and options

A single <details> needs no class: the elements layer styles it. The class only joins a stack.

How it works

Native <details> and <summary>, styled by elements/interactive.css with no class. components/accordion.css adds the joined block and the chevron.

No JavaScript.

  • The summary is the label of the panel; the rest of the details is its content.
  • Closed content is not shown and is out of the reading order until the panel opens.
  • A summary may hold the two glyphs after its text, at the end of the row. Only then is the browser's marker hidden: without them, and in a bare details, it stays.

Without JavaScript

Nothing changes: opening, closing and grouping are the browser's. The accordion is complete without a script. The chevron is CSS too.

Keyboard and ARIA

Tab reaches each summary in order. Enter or Space opens or closes it.

There are no arrow-key shortcuts between panels.

  • Add no role: a <details> already has its semantics, and no ARIA role is allowed on it.
  • Keep links and buttons out of the summary: it is itself the control.
  • The glyphs are decorative (aria-hidden="true"): the <details> element itself holds the state.

Design

When to use

Use an accordion for content that most readers can skip, grouped under short titles.

  • Frequently asked questions and long reference lists.
  • Optional detail under a short answer.

When not to use

Do not hide what every reader needs, and do not use it to move around the site.

  • For the main sections of a site, use a sidebar. For content a reader switches between, use tabs.
  • Do not put an error, a warning or a required step inside a closed panel.
  • With only one or two short answers, show them as plain text.

Do and don't

Writing the content

  • Write the summary as the question or the topic, in sentence case, in a few words.
  • Put the answer first in the panel. Keep it short; link to a page for more.
  • Order the panels as readers ask: most common first.

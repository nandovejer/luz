Inputs

One control for each type of input: the type tells the browser the keyboard, the picker and the validation.

Text

A single-line field for a short answer you cannot list in advance, such as a name or a title.

Shown on the dashboard.
Error: Use letters, numbers and dashes only.
Code Design

Code

Copy the markup

A label and an input need no class. .luz-field adds a hint and an error:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="name">Project name</label>
  <input class="luz-input" id="name" type="text" aria-describedby="name-hint">
  <div class="luz-field__helper" id="name-hint">Shown on the dashboard.</div>
</div>
Variants and options
  • required, with .luz-field__label--required for the red asterisk.
  • Error: .luz-input--error, aria-invalid="true" and a .luz-field__error after the field.
  • disabled: faded, skipped by Tab, not sent.
  • readonly: dashed underline, reachable, sent.
  • list with a <datalist>: suggestions the reader may ignore.
How it works

A native <input> styled by components/form.css. LUZ does not mark a field invalid for you: add the error class, aria-invalid and the message when your validation fails.

Without JavaScript

The field works and submits with its form.

Keyboard and ARIA
  • Tab moves focus into the field, Shift+Tab out of it.
  • The label is the name; the hint and the error are read after it. A placeholder is not a name.

Contrast and focus are in the Design tab.

Design

When to use

Use a text field for a short answer you cannot list in advance.

  • A name, a title, a code, a reference.
  • An address, a number or a date: use the field of that type, such as email, number or date.
When not to use

Do not make the reader type what they could pick.

  • A choice from a list: a select or radio buttons.
  • A password: its field hides what is typed. Several lines: a textarea.
Do and don't
Writing the content
  • The label is a short noun in sentence case: "Project name".
  • The hint says the format or why you ask.
  • The error says what is wrong and how to fix it.
Contrast and focus

Shared with the other inputs: contrast and focus of inputs.

Tokens it uses

Shared with the other inputs: tokens of inputs.

  • The label is the name; the hint and the error are read after it.

Design

When not to use

An email field checks the shape of an address, not that it works.

  • Do not use a text field for an address: the reader loses the check and the keyboard.
  • Do not rely on it to prove the address is real: send a message and ask for confirmation.
Do and don't
Writing the content

  • The hint says what the address is used for.

Password

A field that hides what is typed, for a password or another secret the reader enters.

At least 8 characters.
Code Design

Code

Copy the markup

A text field with type="password". Set autocomplete so a password manager knows what to do:

HTML 
<div class="luz-field">
  <label class="luz-field__label luz-field__label--required" for="password">Password</label>
  <input class="luz-input" id="password" type="password" autocomplete="current-password" minlength="8" required aria-describedby="password-hint">
  <div class="luz-field__helper" id="password-hint">At least 8 characters.</div>
</div>
Variants and options
  • autocomplete="current-password" to sign in; "new-password" to sign up or change it.
  • minlength, maxlength, pattern: the browser checks them when the form is sent.
  • The states are the Text field's: error, required, disabled and read-only.
How it works

A native <input type="password"> styled like any text field. The browser draws dots instead of the characters. LUZ adds no show-password button: one you add is your own script.

Without JavaScript

The field works and submits with its form, and the browser's password manager can fill it.

Keyboard and ARIA
  • Tab moves focus in, Shift+Tab out.
  • The label is the name; the hint says the rules before the reader types. Do not block paste: it lets password managers work.

Contrast and focus are in the Design tab.

Design

When to use

Use a password field for any secret the reader types and that must not show on screen.

  • Signing in, signing up and changing a password.
  • Set autocomplete so the browser can fill or suggest the password.
When not to use

A password field is for secrets, not for every code.

  • A code sent by text message or email: a text field with inputmode="numeric" and autocomplete="one-time-code".
  • Something the reader must see to check it, such as an address: a text field.
Do and don't
Writing the content
  • Label it "Password", not "Enter your password".
  • The hint states the rules before the reader types: "At least 8 characters."
  • The error says what is missing: "Use at least 8 characters."
Contrast and focus

Search

A text field for words to look for, with a search key on phone keyboards and, in some browsers, a button that clears it.

Search by name or topic.
Code Design

Code

Copy the markup

A text field with type="search" inside a form with role="search", so the page has a search landmark:

HTML 
<form role="search">
  <div class="luz-field">
    <label class="luz-field__label" for="search">Search the docs</label>
    <input class="luz-input" id="search" type="search" name="q" enterkeyhint="search" aria-describedby="search-hint">
    <div class="luz-field__helper" id="search-hint">Search by name or topic.</div>
  </div>
  <button type="submit">Search</button>
</form>
Variants and options
  • enterkeyhint="search": the Enter key of a phone keyboard says Search.
  • list with a <datalist>: suggestions the reader may ignore.
  • The states are the Text field's: error, required, disabled and read-only.
How it works

A native <input type="search"> styled like any text field. Some browsers add a button inside it that clears it; that button is the browser's and LUZ does not draw it.

Without JavaScript

Enter submits the form, as a request to your search address. No script is needed.

Keyboard and ARIA
  • Tab moves focus in. Enter sends the search. In some browsers Escape clears the field.
  • The label is the name; the hint and the error are read after it. A placeholder is not a name.

Contrast and focus are in the Design tab.

Design

When to use

Use a search field to find something by words, in a list, a page or a site.

  • A filter above a table or a list.
  • For the whole site, use search, which has a dialog and an index.
When not to use

Do not use a search field for an answer that is a name or a title.

  • A name, a title or a reference: a text field.
  • A choice the reader can list: a select or radio buttons.
Do and don't
Writing the content
  • The label says what is searched: "Search the docs".
  • The button is a verb: "Search".
  • With no results, say so and offer a way out: "No results for “forms”. Try fewer words."
Contrast and focus

With the country code, such as +34 600 000 000.

Code

Copy the markup

HTML 
<div class="luz-field">

</div>
Variants and options
  • autocomplete="tel": the browser fills in the reader's number.
  • pattern: only when you know the format, with an error that says it; the browser checks nothing else.
  • The states are the Text field's: error, required, disabled and read-only.
How it works

A native <input type="tel">. Phone numbers differ by country, so the browser only chooses the keypad and checks no format. Check the number on the server.

Without JavaScript

The field works and submits its text with the form.

Keyboard and ARIA
  • Tab moves focus in, Shift+Tab out. On a phone the keyboard is a number keypad.
  • The label is the name; the hint says the format you accept, and the error says what to change.

Design

When to use

When not to use

A telephone field checks nothing, and it is not for every number.

  • A quantity the reader adds up: a number field.
  • A code or reference made of digits: a text field with inputmode="numeric".
Do and don't

  • The hint gives one example of the format.
  • The error says what to change: "Enter a phone number with the country code."

URL

A field for a web address: the browser checks that it has a scheme such as https:// and phones show a keyboard with the slash.

Start with https://.
Code Design

Code

Copy the markup

A text field with type="url"; autocomplete="url" lets the browser fill it in:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="url">Website</label>
  <input class="luz-input" id="url" type="url" autocomplete="url" placeholder="https://example.com" aria-describedby="url-hint">
  <div class="luz-field__helper" id="url-hint">Start with https://.</div>
</div>
Variants and options
  • pattern="https://.*": only secure addresses.
  • list with a <datalist>: suggestions the reader may ignore.
  • The states are the Text field's: error, required, disabled and read-only.
How it works

A native <input type="url">. When the form is sent the browser checks that the value is a full address with a scheme: https://example.com passes, example.com does not. It accepts any scheme, so before you turn the value into a link, check on the server that it is http or https.

Without JavaScript

The browser checks the address when the form is sent, with no script.

Keyboard and ARIA
  • Tab moves focus in, Shift+Tab out. On a phone the keyboard shows the slash and the dot.
  • The label is the name; the hint says the address starts with https://.

Contrast and focus are in the Design tab.

Design

When to use

Use a URL field when the answer is the address of a page or a site.

  • A website, a profile or a portfolio.
  • Say in the hint that the address starts with https://: the browser refuses one without a scheme.
When not to use

A URL field takes only a full address, and it proves nothing about the site.

  • A path such as /docs/start: a text field.
  • Do not trust the value: the browser does not check that the site exists or is safe.
Do and don't
Writing the content
  • Label it "Website", not "Enter the URL of your website".
  • The hint says how it starts: "Start with https://."
  • The error says what to change: "Enter a full address, starting with https://."

Number

A field for a quantity the reader counts or adjusts in steps, with spin buttons and a check of its range.

From 1 to 10.
Code Design

Code

Copy the markup

A text field with type="number"; min, max and step set what is valid:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="number">Quantity</label>
  <input class="luz-input" id="number" type="number" min="1" max="10" step="1" value="1" aria-describedby="number-hint">
  <div class="luz-field__helper" id="number-hint">From 1 to 10.</div>
</div>
Variants and options
  • min, max: checked when the form is sent, and the limits of the spin buttons.
  • step: the size of a step; step="any" allows decimals.
  • The states are the Text field's: error, required, disabled and read-only.
How it works

A native <input type="number">. The browser adds spin buttons, sends the value written with a dot, and checks min, max and step when the form is sent. The spin buttons are the browser's: LUZ does not style them.

Without JavaScript

The browser checks the number when the form is sent, with no script.

Keyboard and ARIA
  • Tab moves focus in. Up and Down arrows add or take away one step.
  • The label is the name; say the range in the hint.

Contrast and focus are in the Design tab.

Design

When to use

Use a number field for a quantity: something the reader counts, adds or takes away.

  • Items in a basket, guests, seats.
  • Set min, max and step so the check and the spin buttons agree.
When not to use

A number field is for amounts, not for any value made of digits.

  • A postal code, a card or a one-time code: a text field with inputmode="numeric".
  • An approximate value on a scale: a range.
Do and don't
Writing the content
  • Label it for what is counted: "Quantity", "Guests".
  • Put the unit in the label or the hint: "Weight, in kg".
  • The error says the limits: "Enter a number from 1 to 10."
Contrast and focus

A field for a calendar date, with the browser's own picker. The value is always year-month-day.

Pick a day in 2026.
Code Design

Code

Copy the markup

A text field with type="date"; min and max limit the days:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="date">Start date</label>
  <input class="luz-input" id="date" type="date" min="2026-01-01" max="2026-12-31" aria-describedby="date-hint">
  <div class="luz-field__helper" id="date-hint">Pick a day in 2026.</div>
</div>
Variants and options
  • min, max: days outside them are refused and greyed out in the picker.
  • step: the step in days.
  • The states are the Text field's: error, required, disabled and read-only.
How it works

A native <input type="date">. It shows the date in the reader's language and order, and always sends yyyy-mm-dd. The picker is the browser's; its light or dark scheme follows the page's color mode.

Without JavaScript

The field works and submits with its form. A browser with no date picker shows a text field, so say the format in the hint.

Keyboard and ARIA
  • Tab moves between the day, the month and the year. Up and Down change the part with focus.
  • The label is the name; the hint says the limits.

Contrast and focus are in the Design tab.

Design

When to use

Use a date field for a day the reader can pick from a calendar, near today.

  • A booking, a deadline or a delivery day.
  • Set min and max so the picker only offers valid days.
When not to use

Scrolling a calendar is slow for a date far from today.

  • A birth date, or any date decades back: three fields, a number for the day, a select for the month and a number for the year.
  • A month and a year alone: a month field.
Do and don't
Writing the content
  • Label it for what the date is: "Start date", "Delivery date".
  • The hint says the limits, not the format: the picker has one.
  • The error says what to change: "Pick a day in 2026."

Color

A swatch that opens the system's color picker. The value is always a hex color, #rrggbb.

Code

Copy the markup

The class .luz-input is what draws the swatch: a bare color input keeps the browser's own look.

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="color">Accent colour</label>
  <input class="luz-input" id="color" type="color" value="#0066cf">
</div>
Variants and options
  • value: the starting color. With none, the swatch is black (#000000).
  • disabled: faded, skipped by Tab, not sent.
  • The classes and the error are the Text field's.
How it works

A native <input type="color"> with .luz-input[type="color"]: a 64 px swatch with the field's bottom border. The value is always lowercase hex, #rrggbb, with no transparency and no name. The picker is the system's.

Without JavaScript

The field works and submits its hex value with the form.

Keyboard and ARIA
  • Tab moves focus to the swatch. Enter or Space opens the picker, whose keys are the system's.

Code Design

Code

Copy the markup

A slider with min, max and step, and an <output> that shows its value. The slider shows no number of its own, so the output is updated by a few lines of your own script:

HTML 
<div class="luz-field">
  <label class="luz-field__label" for="volume">Volume <output class="luz-output" id="volume-out" for="volume">50</output></label>

</div>
JS 
const range = document.getElementById("volume");
const output = document.getElementById("volume-out");
range.addEventListener("input", () => {
  output.value = range.value;
});
Variants and options
  • min, max, step: the scale and the size of a step.
  • disabled: faded, skipped by Tab, not sent. A range has no read-only state.
  • With no <output> the reader cannot see the number: always add one.
How it works

A native <input type="range">. .luz-input[type="range"] sets accent-color to --luz-brand-primary, so the thumb and the filled track follow the brand. LUZ has no script for the output: yours listens to the input event.

Without JavaScript

The slider works and submits its value. Without your script the output keeps showing the starting value.

Keyboard and ARIA

  • The label is the name; tie the output to the slider with for.

Without JavaScript

Design

When to use

Use a select when the reader must choose one option from a long list they already know the answer to.

  • A country, a year, a time zone: more than six options, one answer.
  • The options are short and the reader can scan them in order.
When not to use

A select hides the options until the reader opens it, and some people find that hard. The six-option rule is LUZ's own.

  • Six options or fewer: radio buttons, so every option stays in view.

Writing the content
  • The label says what to choose, as a noun: "Country", not "Please select".
  • The first option is a prompt with an empty value, so a required field is not answered by default.
  • Sentence case, in an order the reader can predict, such as alphabetical.

Known issues

The open list of a select looks different in each browser and system. This is intended.

  • The closed box is the same everywhere. The list that opens from it is drawn by the browser or the operating system, and it is the one the reader already knows.
  • Browsers that support appearance: base-select (Chrome and Edge 135 and later, Safari 27 and later) also get the list in LUZ's colors, shape and spacing. Firefox shows its own list.
  • On phones, the system's own picker opens, and LUZ cannot style it.

How form fields work

Every control is a native element, styled by components/form.css. The browser owns the state, the keyboard, the validation and the submission.

  • Each control gets its name from its <label>; the hint and the error are tied to it with aria-describedby.
  • LUZ does not mark a field as invalid for you: add .luz-input--error, aria-invalid="true" and the error text when your validation fails.
  • Field text is 16 px at 768 px and below and on touch screens, so iOS Safari does not zoom in.

Without JavaScript every control works and submits with its form. Only what your own script adds is missing, such as live validation.

Measured from the token values of each mode, rounded down. Needs is the WCAG 2.2 AA minimum: 4.5:1 for text, 3:1 for focus rings, borders and icons.

  • Focus: a 2 px --luz-focus-ring outline, 2 px outside the field; the bottom border of a text field also turns to the ring colour, 2 px thick. Checkboxes, radios and the switch track get the same outline.
  • Not colour alone: an invalid field has a 2 px bottom border and an error message in words; a read-only field has a dashed bottom border; the switch thumb moves.
  • Target: text fields are 44 px high.

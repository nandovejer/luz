¿Qué nivel necesito?

  • Tus propios componentes, los colores y el espaciado de LUZ: nivel 1, solo tokens.
  • Botones, formularios, tablas y diálogos listos para usar: nivel 2, tokens y core.
  • Páginas completas: estructura, cabecera, pie de página y búsqueda: nivel 3, el Catálogo, los tres paquetes.
  • Una landing page, con su cabecera, hero y bloques: nivel 3 y los patrones para ese tipo de sitio, que son componentes del catálogo.

Nivel 1: solo tokens

Propiedades personalizadas de CSS: las escalas de color, espacio y tipografía, los roles tipográficos, los puntos de ruptura y las duraciones del movimiento, y los colores de los modos claro, oscuro y de alto contraste. No necesitas ningún otro paquete de LUZ.

$ pnpm add @luz-ds/tokens
HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">

Con un bundler como Vite, importa los archivos en lugar de añadir etiquetas. Un href no puede indicar un paquete: estas rutas solo sirven para import.

Bundler 
import "@luz-ds/tokens/css";
  • El texto corrido y los encabezados usan ET Book, una fuente con licencia MIT que se incluye con los tokens. Los controles, las etiquetas y las tablas usan la sans del sistema, y el código, la mono del sistema.
  • ¿Vas a usar tus propias fuentes? Carga dist/tokens.min.css: contiene los mismos tokens, pero sin reglas @font-face.
  • Comprueba que tus colores cumplen las proporciones de WCAG con npx @luz-ds/tokens@0.2.1 check-contrast o en el navegador.

Nivel 2: tokens y core

Los 33 componentes, los estilos de los elementos HTML sin clases y JavaScript opcional. Carga primero los tokens.

$ pnpm add @luz-ds/tokens @luz-ds/core
HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css">

<!-- Optional: copy buttons, tabs, players, the color mode -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.js"></script>
Bundler 
import "@luz-ds/tokens/css";
import "@luz-ds/core/css";

// Optional: copy buttons, tabs, players, the color mode
import "@luz-ds/core";
  • Todas las páginas funcionan sin el script. Consulta qué aporta cada módulo de JavaScript.
  • ¿Solo necesitas un componente? Carga dist/base.min.css y el archivo que quieras, por ejemplo dist/components/button.min.css.
  • ¿Tienes marcado al que no puedes añadir clases, como Markdown o el de un CMS? Carga classless.css y marca la zona con data-luz-classless.

Nivel 3, el Catálogo: tokens, core y catalog

Seis componentes que necesitan datos del sitio: búsqueda, consentimiento de cookies, modo de color, selector de idioma, submenú y banner. El catálogo necesita core y tokens.

La estructura de la página de cada tipo de sitio, desde la cabecera hasta el pie, también está en el catálogo, una hoja de estilos por patrón: consulta Tipos de sitio.

El catálogo tiene una hoja de estilos por componente: enlaza las que use la página, después de core.

$ pnpm add @luz-ds/tokens @luz-ds/core @luz-ds/catalog
HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/components/search.min.css">

<!-- Optional: core behaviours, and the site search and cookie banner -->
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.js"></script>
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/catalog.min.js"></script>
Bundler 
import "@luz-ds/tokens/css";
import "@luz-ds/core/css";
import "@luz-ds/catalog/components/search.css";

// Optional: core behaviours, and the site search
import "@luz-ds/core";
import "@luz-ds/catalog";

Tipos de sitio

Para empezar una landing page, un blog, una app o un sitio de documentación, ve a Tipos de sitio: un prompt para cualquier LLM y las recetas de cada parte para copiar.

No hay un paquete para cada tipo de sitio. Sus patrones son componentes del catálogo, una hoja de estilos cada uno, con el nombre <kind>-<name>.css. Instala el nivel 3 y enlaza, después de core, los archivos que use tu página:

  • Landing page: landing-header, landing-hero, landing-main, landing-section, landing-stat, landing-footer y landing-glow: la cabecera, el hero, las secciones y el pie de página.
  • Blog o periódico, con cualquier CMS: cms-header, cms-page-header, cms-article-header, cms-article y cms-footer: la cabecera, la cabecera de página y de artículo, el índice y el pie.
  • Aplicación web: app-header y app-dashboard.
  • Sitio de documentación: docs-shell, docs-page-head, docs-rail, docs-example, docs-dodont, docs-pager y docs-page-foot.

El catálogo tiene una página para cada patrón e indica a qué tipo de sitio le encaja.

HTML 
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/tokens@0.2.1/dist/luz-tokens.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/components/landing-header.min.css">
<link rel="stylesheet" href="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/components/landing-hero.min.css">
Bundler 
import "@luz-ds/tokens/css";
import "@luz-ds/core/css";
import "@luz-ds/catalog/components/landing-header.css";
import "@luz-ds/catalog/components/landing-hero.css";
  • Enlaza los archivos de un tipo en el orden de la lista de arriba.
  • Enlaza landing-hero junto con landing-section: el encabezado de una sección comparte sus reglas con el hero.
  • Ninguno tiene un script. El de core es opcional: con el índice de un blog, marca la sección visible; con la barra lateral de una app, marca el enlace actual y cierra el panel al seguir un enlace.

Antes de publicar

  • npm y pnpm instalan automáticamente los niveles inferiores. Yarn solo muestra un aviso, así que indica todos los paquetes, como arriba.
  • En un CDN, fija una versión exacta y añade un hash integrity con crossorigin="anonymous". Calcula el hash a partir del archivo que cargas, como se muestra abajo.
  • Los scripts de core y catalog muestran un aviso en la consola si falta el nivel inferior.
  • Establece lang en <html>: los scripts de core escriben sus textos en ese idioma (se incluyen inglés y español).
Shell 
curl -s https://cdn.jsdelivr.net/npm/@luz-ds/core@0.2.1/dist/luz.min.css | openssl dgst -sha384 -binary | openssl base64 -A

Añade el resultado como integrity="sha384-…" a la etiqueta que carga ese archivo y repite el proceso con cada archivo.

El hash de un script solo cubre ese archivo, no los que carga después. catalog.min.js carga search.min.js en páginas con búsqueda, consent.min.js en páginas con un banner de cookies y mode.min.js en páginas con el modo de color automático.

Asigna a cada uno su propio hash en un mapa de importaciones, antes del primer script de módulo. Funciona en Chrome 127, Safari 18 y Firefox 138 y posteriores; un navegador más antiguo lo ignora y carga los archivos sin comprobarlos.

Un <link rel="modulepreload"> con un hash no protege en Safari ni en Firefox: úsalo solo como indicación para mejorar el rendimiento.

HTML 
<script type="importmap">
{
  "integrity": {
    "https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/search.min.js": "sha384-…",
    "https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/consent.min.js": "sha384-…",
    "https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/mode.min.js": "sha384-…"
  }
}
</script>
<script type="module" src="https://cdn.jsdelivr.net/npm/@luz-ds/catalog@0.2.1/dist/catalog.min.js" integrity="sha384-…" crossorigin="anonymous"></script>

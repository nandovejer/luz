        Documentación · Patrones

        Cabecera de página

        La parte superior de una página de documentación: el epígrafe, el título, una frase y las etiquetas que indican de qué trata.

        • .luz-docs-page-head, __eyebrow, __lead, __meta, __files
        • Sin JavaScript
        • Claro · Oscuro · Alto contraste
        • Sin problemas conocidos
        ℹ
        Esta traducción la ha escrito una IA y todavía no la ha revisado ninguna persona. Leer esta página en inglés

        Ejemplo

        La cabecera de una página sobre cómo instalar una herramienta de línea de comandos.

        Guides · Setup

        Install the command line tool

        Add the tool to a project and check that it runs, in about two minutes.

        • Version 2
        • macOS, Linux and Windows
        • No known issues

        A picture of the head: it holds a title of its own, so it is hidden from assistive technology on this page. Its text is in the markup below.

        The chips wrap on a narrow screen.

        Problemas conocidos

        No se conocen.

        Código Diseño

        Código

        Copiar el marcado

        La cabecera, como primer elemento hijo del contenido:

        HTML 
        <header class="luz-docs-page-head">
  <p class="luz-docs-page-head__eyebrow">Guides · Setup</p>
  <h1>Install the command line tool</h1>
  <p class="luz-docs-page-head__lead">Add the tool to a project and check that it runs, in about two minutes.</p>
  <ul class="luz-docs-page-head__meta">
    <li>Version 2</li>
    <li>macOS, Linux and Windows</li>
    <li><a href="#known-issues">No known issues</a></li>
  </ul>
</header>

        Variantes y opciones

        No hay modificadores. La cabecera es una clase aplicada a un <header> nativo con cuatro partes.

        ClaseEfecto
        .luz-docs-page-head
        En un <header> del contenido: una columna, con separación entre sus partes y espacio debajo. Su h1 usa --luz-text-4xl, o --luz-text-2xl a 640px o menos
        .luz-docs-page-head__eyebrow
        En un <p>: el área y el grupo, en mayúsculas pequeñas espaciadas y con el color secundario. Si incluye un <code> con el nombre de un paquete, este conserva sus mayúsculas y minúsculas. En árabe se omite el espaciado entre letras
        .luz-docs-page-head__lead
        En un <p>: una frase en color secundario y con un tamaño mayor que el del texto
        .luz-docs-page-head__meta
        En un <ul>: las etiquetas. Cada <li> contiene una o dos palabras dentro de un contorno redondeado y mide al menos --luz-control-sm (28px) de alto. Los enlaces que contienen tienen la misma altura
        .luz-docs-page-head__files
        En un <p>, en lugar de las etiquetas y solo en páginas que no sean de componentes: «Archivos:» y cada archivo dentro de un <code>, en una línea pequeña de color secundario

        Cómo funciona

        CSS de @luz-ds/docs. Define el ritmo y los tamaños; las palabras las eliges tú.

        • La cabecera es una cuadrícula de una columna. La separación entre las partes es --luz-space-sm y el espacio debajo de la cabecera es --luz-space-xl.
        • El h1 es un elemento sin clase dentro de la cabecera; esta le aplica estilos según su posición.
        • Las etiquetas enumeran los datos que alguien quiere saber antes de leer: qué archivos y scripts se usan, qué modos hay, si se ha probado y si se conocen problemas. Si una etiqueta lleva a otro sitio, es un enlace.
        • Las palabras largas de las etiquetas se parten en lugar de ensanchar la página, de modo que las etiquetas se ajustan a 320px.

        Sin JavaScript

        No cambia nada. La cabecera contiene texto y enlaces; el paquete no incluye ningún script.

        Teclado y ARIA

        • Orden: el del código fuente: epígrafe, título, entradilla y, después, las etiquetas. Con Tab solo llegas a los enlaces de las etiquetas.
        • Encabezados: el h1 es el único h1 de la página. Un <header> dentro de <main> no es una zona de referencia de tipo banner.
        • Etiquetas: una lista de elementos sencillos que se anuncia como lista. Una etiqueta sin enlace es texto y no recibe el foco.

        La pestaña Diseño incluye Contraste y foco.

        Diseño

        Cuándo usarlo

        Usa la cabecera en la parte superior de todas las páginas de un sitio de documentación, para que el título y el tema de la página estén siempre en el mismo sitio.

        • Una frase que explique qué permite hacer la página.
        • Unas cuantas etiquetas con los datos que ayudan a decidir si seguir leyendo.

        Cuándo no usarlo

        No uses la cabecera para el banner del sitio: contiene el h1 de la página.

        • Usa una sola cabecera por página. Una sección de una página larga lleva un h2, no otra cabecera.
        • Para la cabecera de un artículo de blog, usa la cabecera de artículo de CMS.
        • Una página de landing empieza con el hero.

        Qué hacer y qué no

        Cómo escribir el contenido

        • Epígrafe: primero el área y después el grupo, separados por un espacio, un punto medio y otro espacio: «Guías · Configuración». Escribe en estilo de frase; el estilo aplica las mayúsculas.
        • Título: el tema de la página o una tarea que empiece por un verbo: «Instala la herramienta de línea de comandos». Sin punto final.
        • Entradilla: una frase de unas veinte palabras como máximo, que termine en punto.
        • Etiquetas: entre dos y cinco, de una o pocas palabras. Indica un dato («Versión 2»), nunca un eslogan. «Sin problemas conocidos» enlaza a la lista.

        Contraste y foco

        Todo el texto aparece sobre la superficie de la página. El contorno de una etiqueta es decorativo: la palabra que contiene transmite el significado.

        • Área de activación: las etiquetas y los enlaces que contienen miden al menos 28 por 28 px, por encima del mínimo de 24 px de WCAG 2.2 (2.5.8).
        • Bordes: el contorno de las etiquetas (--luz-divider) es decorativo y no tiene un mínimo.

        Tokens que usa

        Los 12 tokens que leen las reglas de .luz-docs-page-head de components/page-head.css de docs, agrupados por familia. Cada familia enlaza a su página, donde están los valores de todos los modos. En Figma son variables con los mismos nombres; consulta Tokens en Figma.

        Color
        --luz-divider, --luz-text-secondary
        Spacing and sizing
        --luz-control-sm, --luz-space-sm, --luz-space-xs
        Typography
        --luz-font-sans, --luz-text-2xl, --luz-text-4xl, --luz-text-base, --luz-text-lg, --luz-text-xs
        Radius
        --luz-radius-full
